## 东京 vs 大阪：同价流量减半，差的是那条回程

东京的回程实测走 PCCW（AS3491），属于标准国际线路，不是 CN2，也不是 9929/4837 这类国内优化线路。第三方对东京 VM-0.5 做了 159 个国内节点的三网测试：

| 运营商 | 东京平均延迟 | 实际表现 |
| --- | --- | --- |
| 中国移动 | 179ms | 三网里最好，部分节点 40–180ms |
| 中国电信 | 336ms | 去程 163 骨干经美国转 PCCW，绕得明显 |
| 中国联通 | 372ms | 去程 AS4837 经法兰克福转东京，路径最长 |

移动去程走 AS9808 经香港 CMI 转 PCCW，回程 PCCW 转 CMI，所以在移动宽带上还能用；电信和联通的往返都要绕国际段，300ms 以上属于正常水平。国际方向反而干净：东京本地 2ms、到香港约 50ms、到洛杉矶约 113ms、到法兰克福约 237ms。

大阪走的是另一条路。官网写它接 BBIX 和 JPIX，主要 transit 走 SoftBank，第三方测评称三网去程回程都是软银直连、1Gbps 带宽。延迟方面，第三方给出的量级是到上海 50–55ms、到香港 55–60ms、到东京 7–8ms。这组数字来自未完整核验的第三方摘要，只当量级参考用，但和东京电信 336ms 的差距是数量级上的，方向不会错。

这就解释了大阪为什么同价却砍一半流量：SoftBank 的 transit 成本比普通国际带宽贵，Evoxt 用流量额度把差价补回来。如果你在大阪跑超了，加流量的价格是 **Premium $12/TB**，东京 Standard 只要 $3/TB，正好四倍。所以流量吃得多的业务放东京，图线路质量的放大阪。
